# Product

## Platform

web

## Users

主要用户是产品作者本人。使用场景是每日记录市场复盘信息、逐笔交易内容、日复盘、交易截图、执行纪律和行为错误，并在后续回看中形成可追溯的研究与交易资料库。

## Product Purpose

市场日记是一个个人市场研究与交易复盘终端。它把公开的日报/周报研究资料、私有逐笔交易、每日复盘、截图、统计洞察和导出备份放在同一个系统中，帮助用户从市场观察、交易执行到行为改进形成闭环。

成功意味着：每天能快速录入真实交易与复盘信息；之后能按日期、市场、策略、行为标签和盈亏结果追溯原始判断；系统中的统计结果、截图和 Markdown 资料能够支持长期复盘，而不是只展示短期仪表盘。

## Positioning

产品的核心定位是“研究到交易闭环 + 交易行为仪表盘”。相邻产品可以分别记录 Markdown 笔记或交易流水，但本产品的差异在于把市场研究、交易记录、每日复盘、截图证据、执行纪律和行为统计放在同一个可追溯工作流里。

## Operating Context

研究资料与私有交易复盘都通过独立的 Trading Cloud FastAPI 读写。Vben Admin `web-antd` SPA 承载交互界面，浏览器直接访问 API；交易截图存储在私有 MinIO，业务数据与服务端会话存储在本地 PostgreSQL。

`/trading` 模块包含交易总览、交易台账、每日复盘、统计洞察、字典设置、默认汇率和 Excel 导出。

日常使用应支持高频、低摩擦录入，同时保留足够的上下文用于未来复盘。

## Capabilities and Constraints

- 研究复盘支持日报与周报归档、Markdown 渲染、表格、引用、代码块和在线编辑。
- 私有交易支持逐笔记录、未平仓记录、服务端盈亏/R 倍计算、逐笔汇率、执行评分、情绪、错误标签、截图附件和软删除。
- 日复盘支持每日市场计划、交易总结、最佳交易、最大失误、纪律检查和明日改进项。
- 统计洞察按市场、策略、执行等级、情绪和错误模式汇总交易表现。
- 每笔交易最多 10 张截图。
- `trades` 和 `daily_reviews` 使用 `version` 乐观锁，版本冲突必须保护用户已有数据。
- 交易日期以 `Asia/Shanghai` 语境处理。
- CNY 结算时 `fxToCny` 强制为 `"1"`。
- 任何涉及 `grossPnl`、`netPnl`、`pnlCny`、`rMultiple` 的修改都必须保持网页计算与 Excel 导入计算一致。
- 本项目仅用于个人研究与历史复盘，不构成投资建议。

## Brand Commitments

产品名称为“市场日记”。现有语气应保持专业、克制、面向长期复盘，不做投资建议承诺，不伪造收益、外部客户、公开背书或性能数据。

## Evidence on Hand

- `README.md` 记录产品功能、路由、部署和数据来源。
- `AGENTS.md` 记录架构约束、构建流程、数据库并发、交易计算和常见陷阱。
- `reviews/` 包含历史日报、周报和交易规则 Markdown。

- `apps/web-antd/src/api`、`apps/web-antd/src/store/auth.ts` 和各业务页面体现直连 API 与会话工作流。
- Trading Cloud 仓库中的 SQLAlchemy、Alembic、PostgreSQL DDL 和 MinIO 实现是后端数据模型的来源。
- 当前没有可记录的外部客户、公开案例、收益证明或第三方背书；未来设计与文案不得虚构这些内容。

## Product Principles

1. 数据真实可追溯优先于视觉表现和短期便利。
2. 每日录入必须足够快，不能让复盘系统本身成为交易后的负担。
3. 研究资料、交易行为和统计结果应互相连接，形成闭环。
4. 计算口径和原始证据必须稳定，避免因界面改动破坏长期比较。
5. 研究与交易接口都必须经过认证，Cookie、附件和业务数据不能由前端持有密钥后直接访问存储层。

## Accessibility & Inclusion

产品是个人使用的 Web 工具，但后续界面改动仍应保留键盘可访问性、清晰焦点态、足够色彩对比、可读表格和移动端基本可用性。
